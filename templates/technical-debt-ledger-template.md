# 企业级技术债务台账与治理清单 (Technical Debt Ledger & Governance)

> **治理视角**: 架构演进生命周期的记账与清偿契约 (Technical Debt Lifecycle & Repayment)  
> **核心使命**: 秉持“债务显性化、透明化与受控性”原则，建立结构化技术债务台账，量化本金（重构工时）与利息（摩擦成本与系统风险），严查 Agent 时代的“认知债务”，落实“谁借谁还”契约与迭代偿还预算，防止系统陷入破产雪崩。

---

## 1. 技术债务治理策略与偿还预算 (Governance Policy & Debt Budget)

| 治理要素 | 规约配置与执行策略 |
| :--- | :--- |
| **迭代还款预算配额** | **强制 15%~20% 研发产能**：每个敏捷冲刺（Sprint）固定划拨不低于 15% 的 Story Points 专用于清偿高危技债 |
| **借款准入审批门槛** | **重大破窗由 ARB 特批**：架构型技术债务必须申报 `Architecture Exception` 并由业务负责人知情签署 |
| **认知债务重点防线** | **严查提示词打补丁与上下文膨胀**：禁止通过反复向 Prompt 塞自然语言补丁规避工具安全设计 |
| **状态生命周期流转** | `Active (挂账中)` $\to$ `Repaid (已偿还核销)` 或 `Accepted (长期接受风险/随系统报废)` |
| **整顿红线机制** | 当系统未偿高危债务总人天超过阈值（如 > 40 人天）时，暂停承接新非核心特性，全员集中清偿 |

## 3. 重点认知高危债务规格卡片 (Cognitive Debt Cards)

### 3.1 债务编号: DEBT-AI-2026-003 (提示词打补丁替代沙箱防护)
- **债务分类**: 提示词打补丁债务 (Prompt-Patching Debt / "Prompt Hacks")
- **关联架构工件**: `COMP-TOOL`, `COMP-SANDBOX`, `ADR-002`
- **借债背景与商业动因**: 为配合紧急版本上线，开发人员未在执行沙箱底层编写 POSIX 只读属性与命令白名单，而是在 System Prompt 末尾追加了一段长达 200 字的警告文本，告诫 Agent 严禁删除文件。
- **利息与风险评估**:
  - *对抗测试暴露*: 经自动化越狱测试，在受到隐蔽间接注入时有 12% 概率突破防线。
  - *注意力稀释*: 随着 Prompt 越来越长，有效任务达成率衰减约 3.5%。
- **偿还方案与本金估算**:
  - 在沙箱网络策略与运行环境中引入容器只读文件系统挂载: 3 人天；
  - 工具代理网关强行拦截非法写指令并接入 HITL: 2 人天；
  - 清理无用自然语言补丁提示词并回归测试: 1 人天；**合计本金: 6 人天**。
- **偿还契约与到期日**:
  - **责任人**: AI 安全工程师；**批准人**: 首席架构师
  - **截止到期日**: **2026 年 10 月 30 日 (Sprint 18)**
