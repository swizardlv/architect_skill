### 1.2 局部架构模式适配表 (Local Patterns Matrix)
针对非核心域与局部关键子系统，采用局部微模式进行差异化适配：

| 子系统 / 功能域 | 承载职责 | 选定局部架构模式 (Local Pattern) | 采纳理由与特定质量诉求 |
| :--- | :--- | :--- | :--- |
| **接入与过滤层** | 网络连接终结、格式解包与快速阻断 | **管道-过滤器模式 (Pipes & Filters)** | 串行纳秒级预风控，单点不合规立即阻断返回 |
| **核心业务计算域**| 核心业务状态机推进与撮合结算 | **单线程无锁循环模式 (Single-Threaded Loop)** | 消除多核锁争用与上下文切换，保证确定性重放 |
| **规则与策略域** | 费率优惠、风控规则与结算插件扩展 | **微内核/插件模式 (Microkernel / Plugin)** | 支持热插拔动态扩展，隔离自定义规则对核心侵入 |
| **数据查询与报表**| 历史轨迹检索、多维分析与对账导出 | **CQRS 读写分离模式** | 将重型只读查询从高频写入主路径物理剥离 |

## 2. 候选架构风格横向权衡矩阵 (Candidate Styles Trade-off Matrix)

| 评估维度 | 备选方案 1: {如: 微服务架构} | 备选方案 2: {如: 模块化单体架构} | 方案 3 (采纳方案): {如: 空间/内存计算架构} |
| :--- | :--- | :--- | :--- |
| **核心机制** | 独立进程/独立库，基于网络 RPC 协作 | 统一单进程，代码包内部设领域硬边界 | 纯内存对象池常驻，单线程循环+异步落盘 |

| **吞吐能力上限** | 通过节点横向水平扩展增容 | 受限于单机共享数据库连接与锁竞争 | **单物理核达 150 万+ TPS，线性分区伸缩** |

## 3. 五维评判漏斗与自检打分 (The 5-Dimension Evaluation Funnel)

| 检验维度 | 核心检验提问与准则 | 评估现状与结论 | 合格判定 |
| :--- | :--- | :--- | :--- |
| **1. 团队能力可行性<br>(Team Feasibility)** | 团队规模、技能储备与自动化工具链能否支撑该架构的日常迭代？ | 核心研发团队精通底层性能调优与无锁流水线，配备自动化硬件基准测试套件。 | **通过 (PASS)** |
| **2. 关键质量属性拟合<br>(NFR Alignment)** | 是否精准解决了 ARC 中优先级为 P0 的核心业务矛盾？ | 方案精准命中亚微秒时延 (ARC-PERF-01) 与零丢单容灾 (ARC-AVAIL-01) 核心痛点。 | **通过 (PASS)** |
| **3. 架构逆转成本<br>(Reversibility)** | 未来若面临更大规模演进，架构是否具备平滑扩展能力，逆转代价如何？ | 业务逻辑与底层通信框架通过 Facade 接口物理隔离，支持交易标的线性分区伸缩。 | **通过 (PASS)** |
| **4. 基础设施与 TCO 预算<br>(TCO & Budget)** | 硬件采购、专线费用与维护开销是否严格满足初始约束（BC/TC）？ | 采用高性能裸金属物理机，硬件初始投入符合预算约束，单笔交易硬件折旧成本降低 98%。 | **通过 (PASS)** |
| **5. 顶层 ADR 闭环认证<br>(ADR Closure)** | 是否已沉淀为顶层架构决策记录，为负面代价（如内存单点崩溃）制定缓解防线？ | 决策已正式合入顶层 ADR，并配套设计了双机热备与确定性日志回放兜底策略。 | **通过 (PASS)** |

## 4. 架构师避坑自查清单 (Anti-Patterns Check)
- [x] **无简历驱动架构 (No RDA)**: 未因盲目追逐新颖而引入多余的复杂组件，所有组件均有实质业务指标对应。
- [x] **无银弹盲信 (No Silver Bullet)**: 清醒认识到选定风格带来的负面代价（如内存管理门槛高、算力上限受限），并在 OM 中配备专门资源对齐。
- [x] **无架构僵化 (No Dogmatism)**: 未在所有子模块推行一刀切方案，在边缘查询与网关层采用了适配的局部微模式。
