# 架构风格选型与模式裁决规约 (Architectural Style & Pattern Selection)

> **架构视角**: 骨骼结构与宏观运动机制 (The Structural Skeleton & Macro Patterns)  
> **核心使命**: 依据系统质量指标与工程约束，裁决架构技能编排套件的顶层骨架（Macro Style）与子域适配微模式（Local Patterns），形成不可篡改的工程法典，并沉淀为顶层 ADR。

---

## 1. 架构风格核心选型推导 (Style Selection Summary)

### 1.1 宏观主导架构风格 (Primary Macro Style)
- **选定风格**: **微内核与确定性有限状态机架构 (Microkernel & Deterministic FSM Architecture)**
- **选型核心主旨**: 架构套件核心仅保留最精简的生命周期调度器（FSMOrchestrator）与轻量原子状态快照引擎，外部通过标准插件式技能规范（Skills）与模板契约（Templates）挂载需求澄清、结构建模、物理运行、契约决策等各阶段具体实现。状态迁移严格受控于显式转移矩阵与门禁守护（Gatekeeper），杜绝传统 Agent 自由网状调用的非确定性与跳步风险。
- **对应的核心 ARC 条目驱动**:
  - 支撑 **[ARC-PERF-01]**: 状态转移耗时 ≤ 50ms，单进程内存占用 < 120MB。
  - 支撑 **[ARC-AVAIL-01]**: 拦截 100% 非法状态跳转，会话中断后断点无损恢复 RTO < 500ms, RPO = 0。
  - 支撑 **[ARC-SEC-01]**: 插件执行受限运行于安全沙箱与本地受控工作区内。

### 1.2 局部架构模式与认知拓扑适配表 (Local Patterns & Cognitive Topologies)

| 子系统 / 功能域 | 承载职责 | 选定局部架构模式 / 认知拓扑 (Local Pattern) | 采纳理由与特定质量诉求 |
| :--- | :--- | :--- | :--- |
| **状态流转中枢** | 维护当前架构生命周期阶段、确定性转移与中断恢复 | **状态机驱动有向图模式 (StateGraph / FSM Pattern)** | 强制执行单向阶段递进，设最大步数硬限制，支持 REJECT 回退与原子快照 |
| **质量门禁守护** | 各阶段准入准出工件完整性与格式硬校验 | **前置拦截守卫模式 (Gatekeeper Guard Pattern)** | 产物不达标禁止状态跃迁，阻断半成品进入下游，提供死循环硬阻断 |
| **文档打磨引擎** | 对全工作区 Markdown 实施 IBM 标准深度审计 | **管道-过滤器与认知审计模式 (Pipes & Filters)** | 多道质量检查规则顺序过滤扣分，输出结构化诊断报告与整改建议 |
| **看板图元渲染** | 提取 Mermaid 图元并生成多图表可视化 HTML | **模板视图分离模式 (Template View Pattern)** | 将核心状态与图元数据解耦，输出独立无依赖的交互式单文件看板 |
| **意图与任务路由**| 区分标准模板装配与深度非确定性推导任务 | **认知分层架构 (Fast-Slow Thinking / System 1 & 2)** | 简单脚手架生成走快路径，复杂架构推导走慢思考与对立审查双 Agent 回路 |

## 2. 候选架构风格横向权衡矩阵 (Candidate Styles Trade-off Matrix)

| 评估维度 | 备选方案 A: 提示词驱动的网状自主智能体 (Swarm) | 备选方案 B: 静态线性流程脚本 (Linear Pipeline) | 方案 C (采纳方案): 微内核与确定性有限状态机 (FSM) |
| :--- | :--- | :--- | :--- |
| **核心运作机制** | 多个 Agent 自由对话协同，无显式状态机约束 | 固定的单向顺序脚本执行，按部就班运行 | 显式状态转移矩阵，Gatekeeper 门禁硬校验，微内核插件挂载 |
| **执行确定性与死循环控制** | 极低 (易跳步、出现“土拨鼠之日”无休止死循环或自说自话) | 较高 (线性流转，但缺乏交互适应性) | **确定性单向推进，设置 Max Steps 与强制转人工 (HITL)** |
| **质量门禁能力** | 极弱 (仅依赖 Prompt 引导，极易被绕过) | 中等 (基于简单 exit code 判定) | **强类型硬门禁，产物不达标直接拦截并阻止状态迁移** |
| **断点恢复能力** | 差 (依赖上下文窗口重新注入，易丢失进度) | 差 (无细粒度状态持久化机制) | **原生支持本地 JSON 状态快照与无缝原子恢复** |
| **裁决结论** | **否决 (Rejected)** | **否决 (Rejected)** | **采纳 (Accepted)** |
| **被否决致命根因** | 执行轨迹不可预测，无法达成 `ARC-AVAIL-01` 质量要求 | 无法处理人类审查 REJECT 打回与重试循环分支 | 拟合严谨架构工程化诉求，代码复杂度在可控范围 |

| **5. 顶层 ADR 闭环认证<br>(ADR Closure)** | 是否已沉淀为顶层架构决策记录，为负面代价制定工程兜底防线？ | 决策已正式合入顶层 [ADR-001](../03-decisions/ADR-001-fsm-shell.md)，并针对状态并发设计了原子写入防线。 | **通过 (PASS)** |

## 4. 架构师避坑与“死循环防御”自查清单 (Anti-Patterns & Loop-Breaker Check)
- [x] **无简历驱动架构 (No RDA)**: 未因追逐所谓的“多智能体网络 Swarm”而放弃工程确定性，坚守奥卡姆剃刀原则。
- [x] **无银弹盲信 (No Silver Bullet)**: 清醒认识到概率推理的局限，不依赖大模型“自觉”守规矩，引入宿主状态机硬约束。
- [x] **无架构僵化 (No Dogmatism)**: 核心采用状态机调度，而在文档打磨引擎上灵活采用了组合式的管道-过滤器模式。
- [x] **“死循环防御”审查 (The Loop-Breaker Test)**: 当 Agent 调用工具连续报错达阈值（如连续 3 次）时，架构上靠宿主状态机强制介入截断并挂起转人工（HITL），绝不依赖大模型“自主顿悟”。
