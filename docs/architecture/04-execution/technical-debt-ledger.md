# 企业级技术债务台账与治理清单 (Technical Debt Ledger & Governance)

> **治理视角**: 架构演进生命周期的记账与清偿契约 (Technical Debt Lifecycle & Repayment)  
> **核心使命**: 秉持“债务显性化、透明化与受控性”原则，针对架构技能编排与治理套件，建立结构化技术债务台账，量化本金（重构工时）与利息（摩擦成本与系统风险），严查 Agent 时代的“认知债务”，落实“谁借谁还”契约与迭代偿还预算，防止系统陷入破产雪崩。

---

## 1. 技术债务治理策略与偿还预算 (Governance Policy & Debt Budget)

| 治理要素 | 规约配置与执行策略 |
| :--- | :--- |
| **迭代还款预算配额** | **强制 15%~20% 研发产能**：每个敏捷冲刺（Sprint）固定划拨不低于 15% 的 Story Points 专用于清偿高危技术债务 |
| **借款准入审批门槛** | **重大破窗由 ARB 特批**：架构型技术债务必须申报 `Architecture Exception` 并由业务负责人知情签署 |
| **认知债务防范红线** | **严禁提示词打补丁替代安全设计**：杜绝靠自然语言警告掩盖沙箱或工具契约漏洞的行为 |
| **利息控制与防利滚利** | **基线冻结法则 (Baseline Freezing)**：通过 CI 自动化合规扫描，严禁在既有破窗代码上衍生新违例 |
| **状态生命周期流转** | `Active (挂账中)` $\to$ `Repaid (已偿还核销)` 或 `Accepted (长期接受风险/随系统报废)` |

## 3. 重点高危债务规格卡片 (High-Risk Debt Specification Cards)

### 3.1 债务编号: DEBT-AI-2026-003 (提示词打补丁替代沙箱防护)
- **债务分类**: 提示词打补丁债务 (Prompt-Patching Debt / "Prompt Hacks")
- **关联架构工件**: `COMP-TOOL`, `COMP-SANDBOX`, `ADR-002`
- **借债背景与商业动因**: 为保证首期原型极速上线，团队未在受控沙箱内配置系统级命令白名单，而在 System Prompt 末尾追加了警告文本，要求模型不可调用文件删除命令。
- **“利息”与风险评估**:
  - *对抗测试暴露*: 自动化越狱测试显示在特定 Prompt 注入诱导下有 12% 概率绕过限制。
  - *注意力稀释*: 随着自然语言补丁越塞越多，模型对核心设计规则的遵循准确度下降。
- **“本金”偿还工程量估算**:
  - 沙箱执行环境引入只读文件系统隔离: 3 人天；
  - 工具代理网关强行拦截高危删除指令并触发 HITL: 2 人天；
  - 清理无用警告提示词并进行全量回归: 1 人天；**合计本金: 6 人天**。
- **偿还与清偿契约**:
  - **承接团队**: 安全与架构研发组
  - **责任人**: `安全架构工程师`；**批准人**: `首席架构师`
  - **截止到期日 (Due Date)**: **2026 年 10 月 30 日 (Sprint 18)**
