## 2. 用户分类与角色模型 (Personas & User Roles)

### 2.1 角色矩阵
| 角色名称 | 角色定位 | 核心职责 | 核心痛点 | 交互模式 (API / GUI / CLI) |
| :--- | :--- | :--- | :--- | :--- |
| **系统管理员** | 平台运维与基础设施管控 | 监控集群、执行灾备演练、配置配额 | 告警风暴、运维工具割裂 | CLI / Web Console |
| **业务操作员** | 核心业务流执行与日常巡检 | 录入工单、处理异常挂起数据 | 手动重复操作、界面响应迟滞 | Web GUI |
| **外部集成方** | 上下游合作伙伴与上游业务源 | 推送业务事件、同步主数据 | 接口版本不稳定、限流机制不明确 | RESTful / gRPC / Webhook |
| **审计合规员** | 安全合规、追溯与风险复核 | 导出审计日志、验证不可篡改证据链 | 日志分散、证据链不完整 | Web Audit Portal |

### 3.2 关键用例详细规约

#### UC-01: [主线业务核心用例]
- **主参与者**：[用户角色/调用方]
- **前置条件**：[例如：账户已激活、授信额度校验通过、鉴权 Token 有效]
- **触发条件**：[例如：接收到来自网关的结算请求]
- **主成功场景流 (Happy Path)**：
  1. 调用方提交业务请求负载至接入网关。
  2. 接入网关校验签名、解密并执行幂等指纹比对。
  3. 领域核心执行业务不变量校验。
  4. 状态机持久化业务事件至事务日志（WAL）。
  5. 异步投递领域事件至下游消息队列。
  6. 返回 201 Created 与全局唯一业务追踪 ID。
- **备选与异常流 (Alternative & Exception Paths)**：
  - *3a. 业务不变量冲突*：返回 409 Conflict，写入违规审计流水。
  - *4a. 持久化存储不可用*：触发熔断降级队列，返回 503 与重试退避建议。
- **后置条件 (Post-conditions)**：
  - 核心状态推进至 `CONFIRMED`。
  - 状态快照与事件完全可追溯。

## 4. 现有环境与棕地分析 (Existing Environment & Brownfield Analysis)

### 4.1 现有系统拓扑与技术债务
- **现有系统组件**：说明当前运行中的老系统技术栈、部署环境与瓶颈。
- **遗留系统限制**：无法重构的黑盒系统、固定协议（如固定 TCP 私有报文、IBM MQ）。
- **数据共存与迁移风险**：新老系统双写机制、数据一致性校验与回滚策略。

### 4.2 网络与安全基础设施约束
- **网络隔离区划**：DMZ、业务生产区、核心数据区、隔离审计区。
- **加密与凭据管理**：硬件安全模块 (HSM)、KMS、TLS 1.3 强制要求。

## 5. 硬约束与假设编目 (Hard Constraints & Assumptions)

### 5.1 不可违背的硬约束 (Inviolable Constraints)
1. **合规约束**：业务数据必须在境内合规机房落盘，敏感字段落盘加密。
2. **算力与成本约束**：单节点内存占用上限不得超过 [X] GB，冷存储费用预算上限。
3. **技术栈锁定约束**：运行环境仅支持 Linux x86_64 / aarch64，禁止引入未经安全审计的外部依赖。

### 5.2 核心架构假设 (Key Assumptions)
1. **上游时钟假设**：所有输入节点时钟偏差保持在 NTP 同步标准差 50ms 以内。
2. **网络分区假设**：跨可用区光纤网络单向延迟通常 < 2ms，发生不可恢复分区概率 < 0.01%/年。
